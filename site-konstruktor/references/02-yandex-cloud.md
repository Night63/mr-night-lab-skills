# Фаза 2. Yandex Cloud: основа

Перед фазой — сверить цены и интерфейс консоли с документацией yandex.cloud (интерфейс меняется).

## Аккаунт и доступ
- **[П]** Яндекс ID → console.yandex.cloud → облако → платёжный аккаунт (карта) → каталог проекта.
- **[П]** 2FA Яндекс ID — приложение «Яндекс Ключ» (Google Authenticator Яндекс ID не принимает). Включить ПИН на одноразовые коды.
- **[П/C] Утилита `yc` на ПК пользователя.** Установка в PowerShell:
  `iex (New-Object System.Net.WebClient).DownloadString('https://storage.yandexcloud.net/yandexcloud-yc/install.ps1')`
  затем перезапустить PowerShell, `yc init`: вход через браузер, облако, каталог; зону по умолчанию не задавать.
  - Путь по умолчанию: `%USERPROFILE%\yandex-cloud\bin\yc.exe` — в скриптах указывать полный путь.
  - Вход через браузер истекает примерно за 1–2 суток. Тогда команда открывает браузер — пользователь подтверждает.
  - **Никогда** не запускать `yc config list` и всё, что печатает токен или ключи.

## Cloud DNS
- Публичная зона `домен.` (с точкой в конце).
- Голый домен на бакет-сайт — запись **ANAME** на `домен.website.yandexcloud.net`, TTL 600 (обычный CNAME на корне нельзя).
- **Значения TXT пишутся в двойных кавычках.** Несколько значений в одной TXT (SPF + проверка Google) — отдельными строками, каждая в кавычках. При правке TXT не затереть SPF — иначе письма уйдут в спам.
- После запуска: CAA `0 issue "letsencrypt.org"`; `www.домен` — второй бакет `www.домен` в режиме «Переадресация» на `https://домен`, свой сертификат.

## Certificate Manager
Let's Encrypt, проверка через DNS: CNAME `_acme-challenge` (кнопка «Создать запись» в консоли создаёт её в Cloud DNS). Отдельные сертификаты для `домен` и `api.домен` (или один на оба). Автопродление включено.

## Хостинг сайта — Object Storage
- Бакет с **именем, равным домену**. Чтение объектов — публичное; список объектов и настройки — закрыты.
- «Веб-сайт» → «Хостинг»: главная `index.html`, ошибка `index.html` (или своя 404).
- «HTTPS» → сертификат из Certificate Manager. Редирект http → https там же.
- Сайт — бакет, а не функция: проще, дешевле, быстрее. Функция — только для динамики.
- Загрузка: `yc storage s3 cp файл s3://домен/путь --content-type тип`. Типы задавать явно (`text/html`, `text/css`, `application/javascript`, `text/xml`, `text/plain`, `application/zip`, `application/octet-stream` для exe). Проверка: `yc storage s3api head-object --bucket домен --key index.html`.
- Посетители видят старые CSS/JS из кэша — после выкладки Ctrl+F5; при крупных правках менять имя файла (`site.css?v=2` или `site.2.css`).

## Бэкенд (если нужна оплата и выдача)
- **Сервисный аккаунт функции** с минимальными ролями: `ydb.editor` (база), `functions.functionInvoker` (для таймера), `serverless.functions.invoker` для API Gateway — проверить актуальные имена ролей в документации.
- **YDB serverless** — база заказов. Путь базы → переменная `YDB_DATABASE`.
- **Cloud Functions**: Python 3.12, `index.handler`, таймаут 60 с. Код — zip из `templates/server` без тестов.
- **API Gateway** на `api.домен`: маршруты `/buy` (POST), `/order` (GET), `/rk/result` (POST), `OPTIONS`. Домен подключается в шлюзе, CNAME в Cloud DNS, сертификат.
- **Переменные окружения** — единственное место секретов.
  - **Главная грабля консоли:** редактор функции во вкладке «ZIP-архив» создаёт новую версию из того, что прикреплено. Если при правке переменных не прикрепить zip заново — версия будет без кода. Каждая инструкция «поменяй переменную» включает «прикрепи zip ещё раз».
  - Правку переменных с секретами делает пользователь в консоли; Claude готовит точный список «имя → что вписать (из какой записи менеджера паролей)».
- **Таймер** суточной задачи (чистка ПД + копия): `yc serverless trigger create timer --name <функция>-daily --cron-expression "0 3 * * ? *" --invoke-function-name <функция> --invoke-function-service-account-name <SA>`. Cron Yandex — 6 полей, в одном из «день месяца / день недели» стоит `?`.
  - **Проверять в облаке:** `yc serverless trigger list`. В опыте таймер месяц существовал только в коде — чистка ПД не работала.

## Письма Yandex Cloud об изменениях
Проверять, касаются ли они проекта. Бессерверные сервисы (функции, YDB serverless, Object Storage, Postbox) региональные — изменения про зоны и ВМ их обычно не затрагивают, но это проверяется по тексту письма.
