# Фаза 7. Бэкенд покупки и выдачи

Эталон — `templates/server` (выжимка рабочего сервера). Каждая правка — новая версия с номером, автотесты перед выкладкой, в архиве проекта — «что изменилось и как развернуть».

## Поток
1. `POST /buy` {email, offer, consent, lang} → заказ (номер `PREFIX` + 12 цифр, секретный токен 256 бит) → подписанная ссылка оплаты.
2. Платёжка → `POST /rk/result` → проверки → выдача (`delivery.py`) → `OK<InvId>`.
3. Письмо покупателю через Postbox (ошибка письма не ломает ответ платёжке).
4. `thanks.html` опрашивает `GET /order?inv=&t=` каждые 3 с до 2 минут и показывает товар.

## Обязательная безопасность (из внешнего аудита; без неё в опыте можно было получить ключ без оплаты)
- Режим уведомления `IsTest` == режим сервера `RK_TEST` == режим заказа; иначе 400.
- Пустой пароль №2 → 500 и письмо владельцу (а не «подпись совпала»).
- Подпись — `hmac.compare_digest`. Сумма — из базы, не из уведомления.
- Идемпотентность: повтор уведомления не выдаёт товар второй раз (и после возврата тоже).
- IP — из `requestContext.identity.sourceIp` шлюза, не из `X-Forwarded-For`.
- `Cache-Control: no-store` на `/order`; на thanks/fail — `no-referrer` и `history.replaceState`.
- Лимиты: заказов с IP в час, на почту в сутки. CORS — только свой домен.
- SQL только параметризованный. Секреты — только в переменных. Служебные `?r=` — только с `ADMIN_KEY` (compare_digest).
- Капча — когда появятся формы, отправляющие письма без оплаты (повтор ключа, «Мои покупки»): Yandex SmartCaptcha, ≤ 3 писем в сутки на адрес.

## Если товар — программа с лицензией (опыт)
- Ключ `XXXX-XXXX-XXXX-XXXX`, 80 бит, без I/O/0/1.
- Лицензия — сертификат, подписанный RSA-2048 (SHA-256) на сервере; в программе только открытый ключ. **Закрытый ключ — только в переменной функции и офлайн**, никогда в репозиторий и на облачный диск.
- Отпечаток ПК: 2 из 3 признаков (UUID BIOS, серийник платы, MachineGuid), передаются хешами. 2 активации на ключ, переустановка Windows место не тратит, перенос — из программы.
- Пробный период фиксирует сервер по отпечатку. Хартбит программы раз в несколько часов даёт честную метрику «живых» запусков.
- Отдельные маршруты `activate / validate / deactivate / trial` — по образцу; их в шаблоне нет, добавляются под проект.

## Уведомления и метрики
- Владельцу — письмо (или канал, не передающий ПД за рубеж). Почта покупателя — только маской.
- Скачивания — шумная метрика (песочницы антивирусов и браузеров качают файл). Конверсию считать «живой запуск → покупка», исключая свои ПК.
- Тестовые заказы остаются в базе — после тестов отзывать выданный товар.

## Проверка
`?r=setup&k=…` → «Таблицы: OK», режим оплаты, `Receipt: да`, «Не заданы переменные: нет», «Резервное копирование: настроено».
