# Резервное копирование базы

**До первой настоящей оплаты.** В октябре 2026 у Yandex Cloud были недоступны зоны ru-central1; часть данных клиентов без копий была утрачена, копии в Object Storage уцелели.

## Схема (готова в `templates/server/backup.py`)
- Раз в сутки (таймер): все таблицы → JSON → gzip → AES-256-GCM (ключ — scrypt от пароля) → `daily/ГГГГ-ММ-ДД.bk` в закрытом бакете. По понедельникам ещё `weekly/ГГГГ-Wнн.bk` и письмо владельцу «скачай на ПК/флешку».
- Перед записью — сверка числа строк с `COUNT(*)`; неполная копия не пишется.
- Восстановление — UPSERT строк; перед ним автоматически страховочная копия `pre-restore/…`.
- Ошибка — письмо владельцу «Резервное копирование НЕ удалось».

## Облако (скрипт `templates/scripts/_claude_infra.cmd`)
- Закрытый бакет `<проект>-backup`, без публичного доступа, класс standard, лимит 1 ГБ.
- Правила хранения: `daily/`, `manual/`, `pre-restore/` — 30 дней; `weekly/` — 180 дней.
- Сервисный аккаунт `backup-writer` **без ролей на каталог**; доступ только к этому бакету через ACL (READ + WRITE). Так утечка ключа не открывает сайт и базу.
- **[П]** Статический ключ `backup-writer` → `BACKUP_KEY_ID` / `BACKUP_SECRET`.
- **[П]** `BACKUP_PASSWORD` — генерировать криптостойко, не показывая на экране: PowerShell
  `$b=New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b) | Set-Clipboard`
  → сразу в менеджер паролей и в офлайн-копию. Без пароля копии бесполезны.

## Учения (обязательно один раз)
1. `?r=backup&k=…` → «📦 Копия базы: manual/…».
2. `?r=backups&k=…` → копия видна в бакете.
3. `?r=restore&obj=manual/…&yes=1&k=…` → «♻️ Восстановлено…». Сразу после копии безопасно: данные те же.
4. Скачать недельную копию: `yc storage s3 cp s3://<бакет>/weekly/<имя>.bk .` → `python decrypt_backup.py <имя>.bk` → посмотрели JSON → удалили (в нём ПД).

## Нельзя
- Копии базы на Google Диск или в любое зарубежное облако (ПД покупателей → трансграничная передача).
- Пароль копий в чат, в архив, в репозиторий.
