# Фаза 8. Доступы и секреты

## Правила для Claude
- Никогда не просить секреты в чат, не выводить их на экран, не писать в архивы, Диск, память, репозиторий, журналы.
- Не запускать команды, печатающие токены и ключи (`yc config list`, `yc iam create-token`, вывод `.environment` целиком). Проверять только имена переменных и несекретные значения (`--jq ".environment | keys"`, `--jq .environment.RK_TEST`).
- Если секрет случайно попал в чат — сказать пользователю и предложить перевыпустить.

## Что делает пользователь
- **2FA везде:** Яндекс ID — «Яндекс Ключ»; регистратор — что дают (у REG.RU — SMS); платёжка — если 2FA нет (у Робокассы вход по ПИН), то уникальный длинный пароль и 2FA на почте, через которую восстанавливается доступ.
- **Менеджер паролей** — одна запись на проект: все переменные функции, пароли платёжки, ключи сервисных аккаунтов, ADMIN_KEY, пароль копий. Плюс зашифрованная **офлайн-копия** на флешку.
- **Генерация секретов** без показа на экране: генератор менеджера паролей или PowerShell с `Set-Clipboard` (см. 04).
- Статические ключи сервисных аккаунтов — секрет показывается один раз, сразу в менеджер.

## Резервная копия переменных функции
`yc serverless function version get-by-tag --function-name <f> --tag $latest --format json > "%TEMP%\env.json"` → пользователь переносит значения в менеджер → удалить файл. `%TEMP%` в cmd может дать короткий путь (`C:\Users\ABCD~1`) — удалять по тому же пути. Делает пользователь или скрипт без вывода на экран.

## Минимальные права
Отдельный сервисный аккаунт на каждую задачу: функция (база), отправка почты (`postbox.sender`), бакет копий (ACL только на свой бакет). Старые ключи и копии закрытых ключей не держать в рабочих папках — найти и удалить (с согласия пользователя).
